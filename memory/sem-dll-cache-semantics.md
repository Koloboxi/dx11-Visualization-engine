The prebuilt `surface_extender_mesher.dll` keeps an internal cache of the loaded contour, subdivision, offsets, and mesh. **DLL source location (corrected 2026-06-24):** it is NOT bundled in this repo, but it lives in a sibling repo at `C:\Users\kolobox\source\repos\surface_extender_mesher` (`src/2d/sem_exports.cpp`, `src/3d/sem_exports3d.cpp`, `src/3d/isosurface.cpp`, etc.; the canonical export header is `src/common/sem_exports.h`, copied into this repo as `source/external/sem_exports.h`). To ship a new SEM export: implement it there, build the `.sln` (Debug+Release x64), then copy `x64/{Debug,Release}/surface_extender_mesher.lib` (+`.exp`) into this repo's `libs/{Debug,Release}/` and the runtime DLL (Release build) to the repo root. The host links `surface_extender_mesher.lib` (Debug→`libs/Debug`, Release→`libs/Release`); a stale import lib gives `LNK2019 unresolved external __imp_SEM_*`.

**Import-lib actually linked lives in the REPO ROOT, not libs/ (corrected 2026-06-28):** the project's `AdditionalDependencies` lists `surface_extender_mesher.lib` as a **bare filename**, which `link.exe` opens relative to the working directory (the repo root, where the build runs). So the lib that is really linked is `<repo>\surface_extender_mesher.lib` — the copies under `libs\Debug` / `libs\Release` (on `LibraryPath`) are NEVER consulted while the root file exists. A stale root lib gives `LNK2019 unresolved __imp_SEM_*` even after you refresh `libs\{Debug,Release}`. So when shipping a new SEM export, copy the freshly built `surface_extender_mesher.lib` over the **repo-root** copy (and the matching `.dll` to root). Verify a symbol with `dumpbin /LINKERMEMBER:1 <lib> | findstr __imp_SEM_<name>`. (The repo-root DLL currently in use is the **Debug** build of the sibling, not Release as an older note said.)

**Intermediate iso-extraction stages (added 2026-06-24):** offset-and-remesh extraction (`SEM_ExtractIsosurface3D` with `axis != 0`) caches two intermediate stages besides the final `iso_mesh`: `g_cache3d.iso_surface` (the original extracted sheet, pre-offset, oriented outward) and `g_cache3d.iso_flat` (the flat base-plane CDT re-meshed projection, with wireframe edges). Exposed via `SEM_GetSourceIsosurface3D` / `SEM_GetIsosurfaceProjection3D` (return negative when no projection extraction has run). Host side (`SemSession`): `m_isoProjected` is set true after any extraction with `isoAxis != 0` (in `ApplyIsoline` and `PollAsync`), reset in `DropIsoline`; `HasIsoProjection()` gates the `ShowSourceIsosurface3D`/`ShowIsosurfaceProjection3D` toggles (fetched on demand, not serialized) and the two `SEMWindow.h` checkboxes under the isosurface section.

- Only `SEM_LoadCSV3D` clears that cache. `Scene::AddFromCSV3D` is a **pure visual load** (CSV3DLoader only, no SEM call) and never touches the SEM cache — so after a subdivide you can `AddFromCSV3D` the serialized result and still recompute offsets/mesh against the live cache.
- `SEM_SubdivideContour` invalidates previously computed offsets and mesh, so when recomputing the pipeline after a subdivide you must recompute **offsets first, then mesh** (the mesh depends on the offsets the subdivide just dropped).

**Where this lives now (refactored 2026-06-05; moved + split 2026-06-13):** the whole pipeline lives in `SemSession`, now under the scene folder and split into declarations ([SemSession.h](source/graphics/scene/SemSession.h)) and definitions ([SemSession.cpp](source/graphics/scene/SemSession.cpp)). The free helpers (`Stem`, `ComputeStats`, `DetectSemDim`, the `Safe*` SEH wrappers, `SemDetail`) moved into an anonymous namespace in the `.cpp`. `SEMWindow.h` (in `gui/`) is a thin modifier-stack view over the session and includes `../scene/SemSession.h`. See [[sem-staging-selection]] for how the panel binds to a contour.

**Working-dir API (changed 2026-06-13):** the SEM API was reorganized — the paired *compute*/*serialize* calls were merged and the `Ex` variants folded into the base names. There are no more `SEM_Serialize*` functions and no path arguments: `SEM_SetWorkingDir(dir)` sets the output folder once, then `SEM_ComputeOffsets(At)`/`SEM_BuildMesh`/`SEM_ExtractIsoline` (and the `*3D` forms) serialize implicitly into it as `<source-stem><suffix>.csv3d`. Suffixes (from the DLL `sem_exports.cpp`/`sem_exports3d.cpp`): `_mesh`, `_isoline`, `_mesh3d`, `_isosurface3d`. `SemSession::OutPath(suffix)` reconstructs the path; `Bind` sets the working dir to the source's session folder (see session note below). `SEM_SolveThermal`/`SEM_SolveThermal3D` take **no arguments** (`void`). The pre-solve `<stem>_mesh[3d].csv3d` has all node `T = 0`; the solver writes the steady-state `T` into each cached node in place **and rewrites that same mesh file** (sets `has_T`, calls `WriteMesh3D`). So `SemSession::ApplyThermal` re-imports the mesh afterward via `ReloadMeshColored` (focused reload that preserves visibility/stats/path/`m_thermalSolved` and keeps the isotherm — unlike `DropMesh`), recolouring nodes by `T` through `AddFromCSV3D`'s built-in `Lerp(CYAN, YELLOW, T)` gradient. In the async 3D pipeline (`PipelineWorkerBody`→`PollAsync`): if the mesh stage ran, `PollAsync` loads `m_job.meshPath` *after* the worker solved, so it already reads the post-solve file. But a **thermal-only** run (mesh already built, only `runThermal`) leaves `m_job.meshPath` empty — so `PollAsync` has an `else if (m_job.runThermal)` branch that calls `ReloadMeshColored` to recolour the existing mesh (without this, clicking thermal Apply on a 3D mesh left it uniformly CYAN). The green isotherm/isosurface (`SEM_ExtractIsoline`/`3D`) is still extracted from the same `T` field. `SEM_GetProgress(void)` reports progress for both 2D and 3D on `ComputeOffsets(At)`, `BuildMesh`, and `SolveThermal`.

**Offsets are now per-shell files (changed 2026-06-14):** offsets are NO longer one combined `_offsets`/`_offsets3d` file. The DLL writes one file per shell, indexed: 2D `<stem>_offset_<i>.csv3d`, 3D `<stem>_offset3d_<i>.csv3d` (`i = 0,1,…`). There is no offset-count getter, so `SemSession::LoadOffsetShells` probes indices `0..` until a file is missing; `CleanupOffsetFiles` deletes stale `_offset[3d]_*` files BEFORE each compute (sync `ApplyOffsets` and `RecomputeUpToAsync` when offsets will run) so a smaller run doesn't reload leftovers. Each shell loads as its own primitive under an empty `"offsets"` `SceneNode` group (`Scene::AddGroupNode`) that is a child of the source contour; `m_offsets` is now that `SceneNode*` (was `Primitive*`), `OffsetsPrim()`→`OffsetsNode()`, `StagePrim` returns `SceneNode*`, and there is a `SemSession::Alive(Scene&, SceneNode*)` tree-search overload. `Scene::RemoveNode(SceneNode*)` removes the group subtree. `m_offStats` aggregates stats across shells.

**Per-source "session" folders (changed 2026-06-15):** serialized stage products are no longer written flat into the system temp dir. Each source gets its own session folder `%TEMP%/sem/<stem>_<N>/` (N = 1,2,3…), and the working dir is that folder. `SemSession` statics `SessionRoot()`/`ListSessions(srcPath)`/`NewSessionDir(srcPath)` enumerate/allocate them; the chosen folder is stored on `Primitive::semWorkDir` so re-staging via the tree reuses it (empty → `Bind` allocates a fresh one and `create_directories` it before `SEM_SetWorkingDir`). `ImportSource(scene, path, workDir="")` takes the session folder. The old per-stage **Import##off/Import##mesh** buttons (and the `StageImportDir` helper) are GONE — instead, importing a source that already has sessions raises a choice modal (`SEMWindow::DrawImportSessionModal`): pick an existing session (→ `LoadSessionStages` reloads its offsets+mesh via `ImportOffsets`/`ImportMesh`, thermal left unsolved) or "[New session]". `ImportOffsets`/`ImportMesh` remain as the internal reload primitives.

**Vertex-points cross-markers removed (2026-06-14):** the whole apparatus that attached yellow "+" markers to mesh vertices is gone — `VertexPointsGroup`/`IsVertexPointsGroup`, `Scene::AttachVertexPointsGroup`/`GenerateVertexPoints`/`ShowVertexPointsFor`, `Primitive::pointSkin`/`PointSkin`/`SKIN_CROSS`, the `geometryshaderpointscross` shader (+ its `.hlsl` and vcxproj entries), and the "Point skin" combo in `PrimitivesWindow.h`. `Scene::SetNodeVisibleCascade` survives (used by the offsets group + stage toggles) but no longer lazily generates markers.

**Apply = recompute UP TO a stage, dirty-tracked (changed 2026-06-10):** `RecomputeFrom(from)` (re-ran `from`→end) was replaced by `SemSession::RecomputeUpTo(scene, to, silent)`. A stage's Apply button now brings the pipeline up to and **including** that stage and stops — it does not drive the rest of the pipeline to the end. Per-stage staleness lives in `m_dirty[4]` (indexed by `Stage`): editing a stage's params calls `MarkStageDirty(st)` from `SEMWindow.h`; `Bind` (new source) and `ResetStage` set the relevant flags true. `RecomputeUpTo` recomputes a stage only if its own `m_dirty` is set OR an upstream stage was rebuilt this pass (`ran`), so unchanged upstream work is skipped. The offsets-before-mesh cache ordering is still automatic because the stages run in order within one pass. Anything rebuilt marks all stages after `to` dirty so their later Apply redoes them. `RunFullPipeline` clears all dirty flags.

**2D vs 3D pipeline (added 2026-06-09):** `SemSession` now drives both the contour pipeline (`SEM_LoadCSV3D` + `SEM_*`) and the triangle-surface pipeline (`SEM_LoadSurface3D` + `SEM_*3D`, see `sem_exports.h`). Dimension is auto-detected on `Bind` by `DetectSemDim(path)`: a source is **3D** iff it has triangles AND its node cloud is non-coplanar (thinnest bounding-box extent > 1e-3 of the largest); a pure contour or planar patch is 2D. `SemSession::dim` (2/3) then branches every stage (`ApplySubdivide`/`Offsets`/`Mesh`/`Thermal`/`ApplyIsoline`). 3D meshing uses `SEM_MeshParams3D{method, param}` (TetGen, `SEM_TetMethod`) instead of the Steiner method; isoline→isosurface. `SEMWindow::Draw` reads `S.Dim()` to swap the mesh controls and hide the (2D-only) revolution section. Sample 3D surfaces live in `Data/05_forgings_3d/*.csv3d`. The cache-ordering and SEH-wrapping rules below apply to both pipelines (`SafeBuildMesh3D`/`SafeSolveThermal3D`/`SafeExtractIsosurface3D` mirror the 2D wrappers).

**Meshing methods slimmed to free Delaunay (changed 2026-06-17):** the non-free Triangle/TetGen-backed quality variants were removed from the DLL, so the method enums shrank and the host callers were updated to match. 2D `SEM_SteinerMethod` is now just `SEM_STEINER_GRID = 0` (grid CDT): `SEM_MeshParams.param` = interior Steiner spacing (<0 = auto avg edge len), `.margin` = min spacing from offset lines as a multiple of `param` (<=0 = auto 0.45). 3D `SEM_TetMethod` is now `SEM_TET_BAND = 0` / `SEM_TET_LAYERED = 1`: BAND's `param` = Steiner grid cell size (a length, <0 = auto avg edge len); LAYERED's `param` = `use_sdf` flag (0/1, <0 = auto 0 = SDF-free). The removed names (`SEM_STEINER_MAX_AREA`/`MIN_ANGLE`/`SIZING`/`CONFORMING`/`NONE`, `SEM_TET_QUALITY`/`MAX_VOL`/`SIZING`/`NONE`) are gone. Host changes: `SemSession` defaults `meshMethod=SEM_STEINER_GRID`/`tetMethod=SEM_TET_BAND`; `MeshParamFactor`/`TetParamFactor` now always return the mean edge length (knobs are lengths); edge-unit conversion applies for GRID (2D) and BAND only. `SEMWindow.h` drops the multi-option combos: 2D shows only the grid spacing + margin, 3D shows a Band/Layered combo (BAND = spacing drag with model/edge-unit toggle, LAYERED = `Use source SDF` checkbox).

**Winding-highlight + pseudonormals (added 2026-06-27, host-side, no DLL change):** two SEM-window viz features computed entirely host-side from mesh geometry (the DLL exposes no normals/orientation API and none was added). (1) *Uneven-winding highlight* — `SemSession::isoShowWinding` + the "Highlight uneven winding" checkbox in the Isosurface section. `detail::WindingMinorityTris(data)` (SemSessionDetail.cpp) BFS-propagates a consistent orientation over the triangle adjacency graph (two tris sharing an edge agree iff that edge runs opposite ways in them) and flags, per connected component, the smaller orientation class. `BuildIsoDisplay` (SemSessionPipeline.cpp) then paints those minority triangles pure red (`Colors::RED`) via `Scene::AddColoredTriangles` with **ensureCCW=false** (must NOT re-fix winding or the red would vanish); else the plain green `AddFromCSV3DData` path. (2) *Pseudonormals* — angle-weighted `detail::VertexPseudonormals` drawn as a line-list overlay by `BuildPseudonormalLines` (builds a `CSV3DData` of one base→base+n·0.8·meanEdge edge per vertex, fed to `AddFromCSV3DData`): source surface (yellow, from the `m_srcPath` file, parented under source) via `ShowSourcePseudonormals` (checkbox in the 3D surface section); isosurface (cyan, parented under `m_isoline`) via `ShowIsoPseudonormals`. Key wiring: **all** iso-primitive construction (sync `ApplyIsoline`/`FlipIsosurface3D`, async `PollAsync`) now routes through `BuildIsoDisplay(scene, data)` and stashes the displayed geometry in `SemSession::m_isoData` (a `CSV3DData` member — needed because the offset-and-remesh case isn't in the SEM cache). That lets `SetIsoWinding` recolour in place (rebuild only the iso primitive from `m_isoData`, no re-extract) and lets iso pseudonormals compute without re-reading a file. `DropIsoline` drops `m_isoNormals` FIRST (it's a child of `m_isoline`) then clears `m_isoData`; `Bind`/`Unbind`/`Validate` track `m_srcNormals`/`m_isoNormals`.

**Meshing instability:** `SEM_BuildMesh`/`SEM_BuildMesh3D` can throw an access violation deep inside the mesher. `SafeBuildMesh`/`SafeBuildMesh3D` in `SemSession.cpp` wrap the call (`__try`/`__except`, returns -100) so the host app survives instead of crashing. C++ `try/catch` does NOT catch these (they're SEH, not C++ exceptions).
